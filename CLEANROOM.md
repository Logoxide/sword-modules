# Clean-room record

This crate is released under CC0. An earlier version contained routines ported
from libsword (CrossWire's C++ SWORD library, GPL-2.0). This file records how
those parts were replaced, so anyone can judge the result. The git history shows
each step.

## What was replaced

| Part | Origin before | Now |
|---|---|---|
| Entry text normalisation | port of libsword's text preparation routine | `src/normalize.rs` from `docs/spec/entry-text.md` |
| Strong's key padding | port | `src/normalize.rs` from `docs/spec/strongs-keys.md` |
| Cipher key preparation | port | `src/cipher.rs` from `docs/spec/cipher.md` |
| Sapphire II cipher | port of libsword's copy of a public-domain cipher | `src/cipher.rs` from `docs/spec/cipher.md` |
| LZSS decoder | port | `src/lzss.rs` from `docs/spec/lzss.md` |
| Conf line handling | closely followed libsword's line reader | `src/conf.rs` from `docs/spec/conf.md` |
| Versification tables | generated by parsing libsword's `canon_*.h` source files | generated from facts queried through libsword's runtime API (`tools/extract_v11n.py` → `data/versification.json`) |

Not replaced, because they were not ported: the storage-format readers, markup
parsing, rendering, installer and transports. (Markup parsing and rendering have since
moved to the `topos-bible-markup` crate in the topos repository, keeping this
provenance, and this crate no longer depends on it: see "No markup dependency" below.) They were written independently
from knowledge of the file formats and protocols (formats and protocols are
functional interfaces, documented in `docs/spec/formats.md`). The Windows-1252
table in `src/encoding.rs` is the published code-page standard.

## Process (git history)

1. `pre-cleanroom` tag (`Import existing work`): the starting point, including
   the ported code. **Do not publish this commit** (see below).
2. `Add behavioural specifications`: `docs/spec/`, written from observed
   behaviour (libsword probed as a black box through its compiled tools and
   Python bindings), public-domain algorithm descriptions (Okumura's LZSS,
   Johnson's Sapphire II) and format documentation. No code is copied into them.
3. `Remove libsword-derived code`: the ported code and the header-derived tables
   are deleted, and the local copy of libsword's source was deleted from the
   working machine.
4. `spec: correct conf line rules`: differential testing showed the conf spec
   was incomplete; it was corrected from further black-box probes only.
5. `Reimplement removed parts from docs/spec/`: new implementations written from
   the specs, with different structure (e.g. LZSS as a ring-buffer type over
   slice patterns, padding as a parser over digit runs, the cipher split into key
   preparation, key schedule and per-byte step).

## Evidence of equivalence (black box only)

`tools/differential/run.py` compares the new code with libsword's compiled
behaviour on randomised inputs: 200,000 entry-normalisation cases, 20,000
dictionary keys, every index slot (621,118) of all 18 versification systems,
3,000 conf layouts, and LZSS-compressed (verse/chapter/book blocks) and
enciphered (plain and personalised keys) modules produced by `osis2mod`, each
compared entry by entry with `mod2imp`. All pass. The 15 real modules from
Ubuntu's archive also still match libsword byte for byte.

Those results were for the earlier, one-author code. **The two-party rewrite**
(below) was checked the same way in October 2026, against libsword 1.9.0 (Arch
Linux's `sword` and `python-sword` packages, used only through their programs and
by calling the Python module), by a Claude (Opus 5.5) session that had not read
libsword's source, headers or bindings source, any other SWORD reader, or this
repository's code from before commit `c03a2f8`:

* `tools/differential/run.py` (unchanged; it ran on Arch as written), full run:
  200,000 normalisation cases, 20,000 dictionary keys, 621,118 index slots,
  3,000 conf layouts, 3 LZSS modules (verse, chapter and book blocks) and
  6 enciphered modules (3 personalised keys, 3 plain; LZSS and ZIP), each
  module 16,722 entries compared with `mod2imp`. All pass. The first run found
  109 of the 3,000 conf layouts read differently: the conf spec's continuation
  rule was wrong for empty or whitespace-only continuation lines. The spec was
  corrected from further black-box probes (`docs/spec/conf.md`, with a table of
  observed examples) and the code fixed from it.
* **Real modules.** Fifteen modules installed from CrossWire with libsword's own
  `installmgr` into a scratch library (KJV, StrongsGreek, StrongsHebrew, MHC,
  Easton, Josephus, Robinson, DRC, WLC, ChiUns, TR, Vulgate, Nave, Daily,
  Pilgrim; zText, zCom4, zLD, RawLD and RawGenBook) were compared entry by entry
  with `mod2imp` using `examples/compare_imp`: 206,939 entries, no mismatches
  (StrongsHebrew has no `Encoding` and Latin-1 text, so it covers that path).
  Two problems were found first and fixed spec-first: TR and WLC did not open,
  because each ships an index for the testament it lacks without the data files
  (libsword reads that testament as empty; `docs/spec/formats.md`), and MHC
  compared as 32,355 entries against 5,506, because `mod2imp` leaves out a
  commentary slot linked to the slot before it (the reader already agreed with
  libsword; `compare_imp` now lists entries the way `mod2imp` does).
* **Fixtures.** Every fixture module compared with a fresh `mod2imp` dump also
  matches, except one entry in each of the three zLD fixtures (`LZip`, `LLzss`,
  `LBz`): the `@LINK` stored inside a compressed entry, which the crate follows
  on purpose (a deviation listed in `README.md`).
* Still without a libsword reference: the RTF subset, UTF-16 modules, and
  enciphered RawLD and RawGenBook modules.

## Limits — please read

* **Not a two-team clean room.** A strict clean room separates the person who
  studies the original from the person who writes the new code. Here the same
  author (an AI assistant, Claude) read libsword's source earlier, wrote the
  specifications, and then wrote the new implementation from them, after deleting
  its copy of the source. The rewrite was done from the specs, but its author had
  previously seen the original code. If you need the stronger guarantee, have
  someone who has not read libsword reimplement the files listed above from
  `docs/spec/`; the differential tests will tell them when they are done.
* **Versification data** consists of facts (book names, chapter and verse counts)
  obtained from libsword's runtime API. Facts are generally not protected by
  copyright, but the selection of systems mirrors SWORD's.
* **History.** Commit `9eb857f` (tag `pre-cleanroom`) contains the ported GPL
  code. Publish the `release-cleanroom` branch (squashes of the clean tree, with no
  earlier history), never `main`'s history or the tag.
* This is not legal advice. If the licensing matters commercially, have it
  reviewed.

## Second rewrite: the whole crate from the specifications (October 2026)

Everything under `src/` was deleted for the clean-room hand-over (commit `825c0ba`) and
written again by a second party who had not seen the earlier code, libsword, its
bindings, JSword or any other SWORD reader.

### Who, and from what

* **Implementer:** Claude (Anthropic's Claude Opus 5.5), working in this repository
  only, as the "clean" side of a two-party clean room. It did not read
  `../sword-modules` (files, `target/` or git history), libsword, JSword or any other
  SWORD implementation.
* **Inputs:** `docs/spec/` (including `api.md`, the public interface kept unchanged),
  `README.md`, this file, `Cargo.toml`, `tests/`, `examples/`, the data in
  `tests/fixtures.tar.gz` (module files inspected with hex dumps, and the `mod2imp`
  dumps in `ref/`) and `data/versification.json`; the public source and
  documentation of the dependencies (topos-bible, topos-bible-markup, ureq, zip,
  flate2, bzip2, lzma-rs, tar); public standards (RFC 959 for FTP, the RTF
  specification, the Windows-1252 code page); and CrossWire's published
  `masterRepoList.conf` and repository listings (data), fetched while testing.
* **Structure** is the implementer's own: `drivers/` reads bytes (verse, string and
  tree keys, with a shared block reader and cache), `module.rs` turns them into
  entries, `versification/` is generated by a new tool (`tools/v11n_to_rust.py`) and
  `install/` holds the installer, its transports and a small FTP client.

### Spec gaps and how they were resolved

The details are in `docs/spec/gaps.md`; in short:

1. MT and Leningrad: the data repeats the Old Testament as the New. Read as
   Old-Testament-only systems.
2. Dictionary `.dat` records, zLD bodies and blocks, record separators, the sort
   order, `@LINK` inside compressed entries: worked out from the `L*` fixtures.
3. General-book nodes (stale `.dat` records, empty root, when a node has text, path
   form): from the `GBook` fixture.
4. RawFiles notes (name records, deleted notes, unnormalised text): from the
   `Personal` fixture; file names are restricted so they cannot leave the module.
5. XZ zero padding and the block index's unused unpacked size: from `TXz` and the
   other `T*` fixtures.
6. UTF-16 text and normalisation (which cuts at NUL): decoded first, then normalised
   (choice; no fixture).
7. Missing `Encoding`/`SourceType` (from `README.md`), and which XML markup to assume
   (choice: TEI, OSIS or ThML by telltale elements).
8. RTF details (control-word delimiters, `\uN` fallbacks, negative `N`): from the RTF
   specification.
9. Conf details (what counts as whitespace, lines before a section, case of values,
   `set` with repeated keys, whitespace-only `CipherKey`): choices, written down.
10. RawLD with a cipher: only the body is deciphered (choice; no fixture).
11. Installer protocol details (master list grouping, source kinds, package names,
    catalogue fallback, `InstallSource*` keys, which open failures still install,
    safe data directories, HTML and FTP listings): from `README.md`, the published
    master list and choices, all written down.
12. Not a spec gap but a hand-over gap: three of the handed-over files
    (`tests/install.rs`, `examples/sword.rs`, `examples/compare_imp.rs`) are formatted in
    a way no single rustfmt configuration reproduces. They are kept unchanged and
    listed under rustfmt's `ignore` option in `rustfmt.toml`, which needs a nightly
    rustfmt (`cargo fmt --check` passes with the nightly toolchain installed here; a
    stable rustfmt warns about the option and reports those three files). Likewise
    clippy's `suspicious_map` fires on `tests/fixtures.rs` and is allowed in
    `Cargo.toml`, and the `sword` example is gated on the `install` feature it uses.

### What was and wasn't verified

* `cargo test`: 24 unit tests, 9 fixture tests (1 more, the real-library smoke test,
  is ignored by default), 3 installer tests and 2 doc tests pass; `cargo clippy
  --all-targets -- -D warnings` (also with `--no-default-features`) and
  `cargo fmt --check` are clean.
* **Fixtures.** Every fixture module (all verse drivers, BOOK/CHAPTER/VERSE blocks,
  ZIP/LZSS/BZIP2/XZ, the enciphered module, the Synodal module, RawLD/RawLD4/zLD,
  the case-sensitive dictionary, the general book, the personal notes) reads back
  entry for entry identical to libsword's `mod2imp` dumps (`examples/compare_imp`
  against `ref/TRaw.imp`, `ref/LRaw.imp` and `ref/GBook.imp`: 289, 316 and 12
  entries, no mismatches). The installer tests install them over HTTP and `file://`,
  from package zips and file by file, byte for byte.
* **Real modules.** Fifteen modules installed from CrossWire's repository with this
  installer over HTTPS (KJV, StrongsGreek, StrongsHebrew, MHC, Easton, Pilgrim,
  Josephus, Robinson, Daily, DRC, WLC, ChiUns, Nave, TR, Vulgate) all open and every
  entry parses (`real_library_smoke_test`), and spot checks read correctly. A module
  was also installed over FTP from ftp.crosswire.org, and real FTP and HTTPS directory
  listings parse. These show the code reads real data; they are not a comparison with
  libsword.
* **Not verified:** libsword is not installed on this machine, so
  `tools/differential/run.py` (randomised comparisons of normalisation, key padding,
  every index slot, conf layouts, LZSS and the cipher against libsword) could not be
  run. The rules it checks were implemented from the specs and tested against every
  example the specs give, and the slot layout was checked against the fixtures'
  index sizes, but not against libsword's randomised cases. In particular the
  personalised cipher keys, the RTF subset, conf continuation edge cases beyond the
  spec's examples, UTF-16 and Latin-1 modules, RawLD/RawGenBook enciphering, and the
  less common versifications have no libsword reference here. Run
  `tools/differential/run.py` on a machine with `libsword-utils` and `python3-sword`
  before relying on them. (Since done, in October 2026: see "Evidence of equivalence"
  above.)

### Limits of this rewrite

* **The implementer is an AI model.** Its training data may have included public
  SWORD source code (libsword, JSword, or code derived from them), and this process
  cannot rule that out. It did not consult any such code during the work and wrote
  from the specifications and fixtures above, but a model cannot show what it has
  not been trained on. The clean room separates the people (and sessions) that
  studied libsword from the one that wrote this code; it cannot separate this
  model's training from it.
* The specifications themselves were written by someone who had read libsword (see
  "Limits" above); they describe behaviour, not code.
* This is not legal advice.

### Disclosure: the implementer read parts of the old markup crate

The second rewrite's rules allowed reading its dependencies' source, which included
`topos-bible-markup` (`../topos/crates/topos-markup`). That crate came from the old
sword-modules and shares its provenance, which wasn't known when the rules were written. Asked
afterwards, the implementer said it had opened, through shell output only:
- in `src/lib.rs`, the module list, `Markup`, `Node`, `Kind`, and the bodies of `parse`, the
  plain-text parser, and `Strongs` (`parse`, `parse_list`, `dictionary_key`, `Display`);
- `TextOptions` in `src/text.rs`;
- the start of `HtmlRenderer` in `src/html.rs`;
- signature greps of the other files.

None of that is about SWORD's storage formats, conf rules, normalisation, the cipher,
versification, or the installer. The one place it shaped this crate is the order of key forms
`DictionaryModule::get_strongs` tries (gaps.md), so that function was rewritten by an agent that
had seen neither the old markup crate nor the old sword-modules (see the next entry).
`topos-bible-markup` has since been replaced by its own clean-room rewrite (topos's
`crates/topos-markup/CLEANROOM.md`).

## `get_strongs` rewritten by a second clean implementer

`DictionaryModule::get_strongs` was the one function the earlier implementer's reading of the old
topos-bible-markup source could have shaped (which keys it tried, and in what order). In October
2026 it was deleted unread and written again by another Claude (Opus 5.5) session, the
implementer of the clean topos-bible-markup (`../topos-bible-markup-cleanroom`). That session has
seen neither the old markup crate nor libsword or any other SWORD reader. It worked from
`docs/spec/api.md`'s doc comments for `get` and `get_strongs`, `docs/spec/strongs-keys.md`, the
dictionary fixtures, and the clean crate's `Strongs` API. It did not read the old function body,
the old gaps paragraph about it, or this file's disclosure section. The lookup order and the
reasoning for it are in `docs/spec/gaps.md` ("get_strongs rewritten by a second clean
implementer"). It was tested against the clean topos-bible-markup in a scratch build, where
`cargo test` passes.

## Reading through `Files` (October 2026)

The readers stopped opening files themselves: `src/files.rs` adds the `Files` trait (read a
file, list a folder, open one to read at offsets) with `FsFiles` (a folder, as before) and
`MemoryFiles`, and the drivers, `Module`, and `SwordLibrary` read through it, so logoxide can open
a module from a zip in memory (and in WebAssembly). The interface went into `docs/spec/api.md`
first. This is plumbing: no format, conf, normalisation, or versification rule changed, and
`DataFile` reads the same bytes at the same offsets as before.

It was written by a Claude (Opus 5.5) session working for logoxide that had not read libsword's
source, headers, or bindings, nor any other SWORD reader, nor this repository's code from before
the clean-room rewrite (only the current `src/`, `docs/spec/`, and the examples). It used
libsword's compiled `mod2imp` once, black-box, to check that an odd entry of the ISV module (its
John 1:0 holds Luke 23:56's text) is what libsword reads too. `cargo test` (with the real-library
smoke test against CrossWire's KJV), `cargo clippy --all-targets -D warnings` with and without
default features, `cargo +nightly fmt --check`, and a `wasm32-unknown-unknown` build without
default features pass.

## Linked verses as spans, and Strong's lexicon keys (October 2026)

For logoxide's SWORD imports, which used to guess linked verses by comparing entries' text (and
so merged notes that merely matched), `VerseModule::iter_spans` gives each run of linked slots
once as a `VerseSpan` (first and last verse, entry, `EntryLocation`), and `VerseModule::location`
gives a verse's location, so slots sharing an entry out of a run can be told apart from equal text
stored twice. `DictionaryModule` gained `link_at` (an `@LINK` alias's target), `strongs_language`
(`Feature=GreekDef`/`HebrewDef`), and `strongs_at` (a key as a Strong's number). The interface went
into `docs/spec/api.md` first, with the run rules (never across a book; empty chapter
introductions passed over), and `docs/spec/formats.md` records how libsword's writers lay out
links. The link itself is the one `formats.md` already defined (identical index entries).

Written by a Claude (Opus 5.5) session working for logoxide that had not read libsword's source,
headers, or bindings, nor any other SWORD reader, nor this repository's code from before the
clean-room rewrite (only the current `src/`, `docs/spec/`, and the tests). It used libsword
1.9.0's compiled `osis2mod` and `imp2vs` black-box, on a small OSIS commentary and an imp file,
reading the index files with a hex dump and slot numbers through the Python bindings'
`VerseKey.getTestamentIndex`: `osis2mod` links only the verses an `osisID` names (an empty John 4:0
between John 3:36 and 4:1), `imp2vs` every slot of a range (John 7:0 in `6:71-7:1`), and a link
into another chapter or book points into the first slot's block. `iter_spans` reads those modules
(RawCom, zCom with chapter blocks, RawText) as the spec says; the tests rebuild the same layouts
synthetically. `cargo test`, `cargo clippy --all-targets -D warnings` with and without default
features, `cargo +nightly fmt --check`, and a `wasm32-unknown-unknown` build without default
features pass.

## No markup dependency (October 2026)

The crate stopped depending on `topos-bible-markup` (logoxide's PLAN-CRATES.md, decision C4; the
markup crate moves to logoxide as `logoxide-markup`). `Markup` became the crate's own enum in
`conf.rs` (SWORD's `SourceType`: OSIS, ThML, GBF, TEI, plain text), and an `Entry` is its `raw`
text and `markup` only: the `markup` re-export, `Entry::nodes`, `plain_text`, `plain_text_with`,
`html` and `strongs`, and `DictionaryModule::strongs_language` and `strongs_at` were removed.
`get_strongs` takes the number as a string (`G25`, `H0430a`) instead of a markup `Strongs`, and
tries the same keys in the same order (`docs/spec/gaps.md`). `iter_spans`, `EntryLocation`,
`VerseSpan` and `link_at` stay, since they use only topos-bible. The interface went into
`docs/spec/api.md` first. No format, conf, normalisation, or versification rule changed, and the
markup an entry is given (named or sniffed) is decided as before; the markup parsing that was
removed was never this crate's code (see "Not replaced" above).

Written by a Claude (Opus 5.5) session working for logoxide that had not read libsword's source,
headers, or bindings, nor any other SWORD reader, nor this repository's code from before the
clean-room rewrite (only the current `src/`, `docs/spec/`, the tests and examples, and the
`Markup` enum's declaration in topos-bible-markup, to keep its variant names). It changed only
signatures and the parsing of `get_strongs`'s argument, not the lookup order. `cargo test`,
`cargo clippy --all-targets -D warnings` with and without default features, `cargo +nightly fmt
--check`, and `wasm32-unknown-unknown` builds without default features (and with `zip`, `bzip2`,
`xz`) pass; logoxide's tests pass against it in a scratch build.
